# 标准分析流程

## 1. 明确授权和目标

在开始前写清：样本来源、所有者、授权范围、允许的测试方式、数据处理要求以及最终问题。例如“确认自有客户端如何解析某文件格式”比“看看它做了什么”更可执行。

## 2. 建立隔离环境

- 未知或不可信样本使用可回滚虚拟机，关闭共享剪贴板、共享目录和不必要的宿主集成。
- 网络默认断开；确需联网时使用隔离网络、受控 DNS/HTTP 模拟或完整流量记录。
- 不在生产账号、日常工作站或存有凭据的环境运行样本。
- 记录操作系统、工具版本、虚拟机快照和时间设置。

## 3. 保全原始样本

只读保存原件，对工作副本分析。至少记录 SHA-256、文件大小和获取时间。

```bash
sha256sum sample.bin
stat sample.bin
file sample.bin
```

不要仅凭扩展名判断格式，也不要将未知文件上传到公共分析服务，除非授权允许样本对外披露。

## 4. 快速分诊

按由低风险到高信息量的顺序进行：

1. 文件格式、架构、编译时间等元数据；
2. 哈希、签名、节区与熵；
3. 可读字符串、资源、导入导出；
4. 编译器、运行时、打包器或混淆器线索；
5. 程序入口与可能的业务关键函数。

目标是决定下一步工具，而不是一次性“跑完所有扫描器”。

## 5. 静态分析

建立可维护的分析数据库：

- 识别入口、初始化逻辑、导入包装函数和错误处理；
- 从独特字符串、资源、导入 API 和交叉引用切入；
- 重命名函数/变量，补充参数类型、结构体和注释；
- 画出关键数据流与调用关系；
- 每个重要结论保留地址、字节、交叉引用或截图依据。

对反编译结果保持怀疑。遇到奇怪类型、失真的循环或缺失边时回到汇编视图验证。

## 6. 动态验证

根据静态假设设置少量高价值观测点：入口、解析函数、比较函数、系统调用、文件与网络边界等。关注：

- 进入函数时的参数和内存对象；
- 分支条件实际取值；
- 调用前后的缓冲区变化；
- 文件、注册表、进程、系统调用和网络副作用；
- 多次运行及不同输入是否得到一致结果。

不要无目标地单步整个程序。优先用断点、日志、trace 或插桩缩小范围。

## 7. 形成结论

报告至少包含：

- 范围与授权假设；
- 样本哈希、环境和工具版本；
- 已确认事实、推断及未解决问题；
- 能复现结论的步骤；
- 风险、影响和修复建议（如适用）。

## 8. 清理

按授权要求保留或销毁样本、内存转储和流量记录；撤销临时凭据；恢复虚拟机快照。分析资料中可能包含密钥、个人数据或恶意载荷，不能默认公开提交。
