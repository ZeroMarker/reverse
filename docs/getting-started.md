# 入门基础

## 逆向工程在做什么

逆向工程是从可执行文件、运行状态、文件格式或通信行为推断程序设计。常见合法用途包括：

- 理解没有源码的自有旧系统；
- 兼容第三方文件格式或协议；
- 审计软件安全性和隐私行为；
- 定位崩溃、性能问题及供应链风险；
- 分析恶意样本并制作检测规则。

逆向得到的是“证据支持的模型”，不是原始源码。符号会丢失，优化会重排控制流，反编译器也可能给出看似合理但错误的伪代码。

## 三类分析

### 静态分析

不运行目标，检查文件头、节区、字符串、导入导出、资源、汇编及反编译结果。优点是可控、易复现；缺点是容易受到混淆、加壳、动态加载和自修改代码影响。

### 动态分析

在受控环境运行目标，通过断点、单步、内存观察、系统调用或网络流量确认行为。它更接近真实执行，但必须隔离未知样本，并注意反调试、时间依赖和环境差异。

### 混合分析

先用静态分析建立假设，再用动态证据验证；将运行时地址、参数和返回值回填到静态数据库。这通常是效率最高的方式。

## 必备知识

### 数字与内存

- 熟悉二进制、十六进制、有符号/无符号整数和大小端。
- 理解虚拟地址、文件偏移、栈、堆、代码段、数据段和内存权限。
- 能识别 ASCII、UTF-8、UTF-16、结构体、指针与常见序列化格式。

### 汇编与 ABI

至少选择一种主流架构深入学习：桌面端优先 x86-64，移动端优先 AArch64。重点不是背指令，而是理解：

- 寄存器、标志位、寻址方式与控制流；
- 函数序言/尾声、参数传递、返回值与栈对齐；
- Windows x64、System V AMD64 或 AAPCS64 调用约定；
- 编译器如何实现条件、循环、switch、对象和异常处理。

### 可执行文件格式

| 平台 | 常见格式 | 重点结构 |
| --- | --- | --- |
| Windows | PE/COFF | DOS/NT 头、节、导入导出、重定位、资源、TLS |
| Linux/Unix | ELF | ELF 头、Program/Section Header、动态段、符号、重定位 |
| macOS/iOS | Mach-O | Load Commands、Segments、Symbols、Code Signature |
| Android | APK/DEX/ELF | Manifest、resources、DEX、签名、原生库 |
| .NET | PE + CLI 元数据 | Assembly、Type/Method 元数据、IL、资源 |

## 建议学习路线

1. 用自己编写的 C/C++ 小程序练习，分别以 `-O0`、`-O2` 编译并比较。
2. 学会读取文件头、字符串、导入表和函数调用图。
3. 在反汇编与反编译视图之间交叉验证，主动重命名函数和变量。
4. 使用调试器观察参数、返回值、内存与关键分支。
5. 分析公开的 CTF/reversing 练习或 crackme；不要从真实商业软件起步。
6. 逐渐加入 Android、.NET、固件或协议等平台专题。

## 一个重要习惯

把结论分成三级：

- **事实**：文件哈希、导入函数、实际捕获的参数等直接证据；
- **推断**：由多个事实支持但仍可能被推翻的解释；
- **待验证**：下一步实验要回答的问题。

这种记录方式能避免把伪代码、函数名猜测或一次运行结果误当成确定事实。
